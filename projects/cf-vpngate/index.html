cf-vpngate

前端 VLESS over WebSocket / XHTTP，后端 SSTP（VPN Gate）+ ProxyIP 落地

一句话概括：这不是普通的「WebSocket → connect() → 目标」字节转发。当后端走 SSTP 时，Worker 会在脚本里完成 SSTP 建链 → PPP（LCP / PAP / IPCP）协商 → 拿到虚拟 IPv4 → 手工封装 IPv4/TCP，再与目标通信。

GitHub 仓库 上游 jacobax/snippets ← 返回项目列表

VLESS WebSocket XHTTP SSTP / PPP ProxyIP 协议研究 · 学习性质

这是协议研究与学习性质的代码，不是稳定可用的 VPN 客户端，不做任何可用性承诺。请遵守所在地法律法规与 Cloudflare 服务条款，仅用于协议学习与合法的网络访问。

架构

客户端 (v2rayN / Xray / sing-box ...)
   │  VLESS over WebSocket  或  VLESS over XHTTP
   ▼
Cloudflare Worker  ── 本仓库
   │
   ├─ 直连（默认优先）：connect(目标)
   │
   └─ 落地（proxyip / SSTP / socks5 / http(s)）：
        ├─ ProxyIP         → connect(proxyip:443)，由它按 SNI 反代到目标
        ├─ SSTP            → SSTP over TLS → PPP → 虚拟 IPv4 → 手工 TCP → 目标
        ├─ socks5 / http(s) → CONNECT 目标
        └─ 域名!txt         → 取 TXT 记录里的任意一种地址，随机选一个
   ▼
目标网站 / 目标服务器

SSTP 后端的完整链路：

VLESS over WS/XHTTP
  → Cloudflare Worker
  → SSTP over TLS (SSTP_DUPLEX_POST)
  → PPP：LCP → PAP → IPCP
  → PPP 分配的虚拟 IPv4
  → 手工 IPv4 + TCP 封包（SYN / ACK / PSH / FIN、序号、窗口、校验和）
  → 目标 TCP 服务

这次重构做了什么

项目旧版 CF-SoftEther重构后 cf-vpngate
入站仅 VLESS over WebSocketWS + XHTTP（含 Early Data）
后端仅 SSTP（path 里写死 sstp://）SSTP + ProxyIP + !txt + socks5 + http(s) 统一调度
DNS每次请求都打 DoHDoH 结果缓存 3 分钟 + 同域名并发去重
上行逐条 write分片入队 + 出队合并，队列 8MB 上限，带反压
下行逐块 ws.send攒包到 64KB + bufferedAmount 背压感知 + scheduler.wait 让出
读取方式默认 reader优先 BYOB（零拷贝）读
半关闭无allowHalfOpen，正确收发 FIN
UDP不支持53 端口（DNS）转成 TCP 上的 DNS 查询再回写
代码结构一个函数流、缩写变量14 个分区、命名函数、CONFIG 集中配置、异常统一收口
部署形态只能当 WorkerWorker（wrangler）与 Snippets（粘贴）都能用

冲突处理原则：凡是与上游 snippet.js 行为不一致的地方，以上游为准（握手超时、early data 来源、!txt 处理顺序、xhttp 响应头、UDP/53 方案等）。

部署

# 方式一：Wrangler（推荐，可保留 wrangler.toml）
npm i
npx wrangler login
npm run deploy          # 等价于 wrangler deploy

# 方式二：Dashboard 新建 Worker
新建 Worker → 快速编辑 → 粘贴 worker.js 全文 → 保存并部署 → 绑定自定义域

# 方式三：Cloudflare Snippets
规则 → Snippets → 新建 → 粘贴 worker.js 全文 → 部署

Snippets 没有环境变量，改 UUID 直接在文件顶部改 CONFIG.uuid，或写全局变量 UUID = "..."。若出现 1101，删掉旧片段 / 旧 Worker 后重新部署。

路径与参数

/fdip=<落地地址>?ed=2560[&global=1][&auto=1]
  • fdip：键名可任意（proxy、p、1234 都行），值就是落地地址；
  • ed=2560：Early Data，客户端侧参数，放最后；
  • global=1：强制走落地（默认先尝试直连，失败再回落）；
  • auto=1 / auto=2：自适应 proxyip。
写法含义
1.2.3.4:443、[2001:db8::1]:443ProxyIP 直连
proxy.example.comProxyIP 直连（默认 443）
sub.example.com!txt取该域名 TXT 记录里的一条地址（逗号 / 换行分隔，随机选）
sstp://host:443SSTP（VPN Gate / SoftEther），默认 vpn:vpn
sstp://user:pass@host:443自定义 PAP 认证的 SSTP
socks5://host:1080SOCKS5 落地
http://host:8080、https://host:443HTTP CONNECT 落地

自助节点页 /sub

返回纯文本：ws 链接、xhttp 链接、可直接复制的 xhttp extra，自动使用请求的 Host。其它任何非代理请求一律返回 204，不暴露页面。

UDP(53)

VLESS 的 UDP 只处理 53 端口（DNS）：Worker 把 DNS 查询包通过 TCP 发给 1.1.1.1:53，拿到带长度前缀的应答后原样回写给客户端（Worker 环境无原生 UDP 出站，其它 UDP 目标直接断开）。

限制与已知问题

  • SSTP 后端只模拟必要的 IPv4/TCP 路径，不是完整网络栈——SACK、窗口缩放等 TCP 选项未实现；
  • 只适合 TCP 目标，UDP 仅 53；
  • 兼容性取决于 SSTP/SoftEther 服务端行为（不同版本对 IPCP、PAP 的处理有差异）；
  • 大流量、长连接会受 Workers 运行时限制（CPU 时间、内存、并发连接数）；
  • VPN Gate 公共节点随时可能下线，需要自行维护列表（优先选 443 端口）；
  • mss 不要改大：TCP 伪首部缓冲区固定 1432 字节（12 + 20 + 1400）。

排障

现象排查
1101删除旧 Worker / 旧片段后重新部署
连不上（ws）确认 Upgrade: websocket、path 中的 UUID 与 CONFIG.uuid 一致
xhttp 无响应确认 type=xhttp、mode=stream-one、Content-Type: application/octet-stream
SSTP 落地失败换节点、确认 443 端口、wrangler tail 看是否卡在 PPP；把 CONFIG.debug 设为 true
目标被重置试 global=1 强制走落地，或换 ProxyIP / 换 SSTP 节点
