cf-b2-worker

Cloudflare Workers ⇄ Backblaze B2 一体化网关：单文件、零依赖、自带 SigV4 与网页文件管理器

一句话概括：一个 Worker 文件，把 Backblaze B2 私有桶变成既能 CDN 加速、又能读写管理的对象存储网关——密钥永不过期、匿名只读一个公开目录、下载强制经 Worker、回源与出网双向免流量费。

它解决什么问题

B2 的存储价格极低，且和 Cloudflare 同属 Bandwidth Alliance——CF 回源到 B2、B2 出网到 CF 都不计流量费。所以「Worker + B2」几乎是零成本私有图床 / 网盘的最优解。但现有的两个上游实现各有明显短板，于是有了这次分析、对比与重写：

上游项目做法关键短板
CF-Proxy-B2 用 aws4fetch 补 SigV4 签名，只读代理 B2 的 S3 兼容 API 只有 GET/HEAD；完全无鉴权（拿到域名就能读私有桶）；依赖打包链脆弱（assert 导入断言已被 V8 移除、.html 缺 loader）；真实密钥被提交进仓库
cw4b2 用 B2 原生 API 换 7 天下载授权令牌，cron 每周再生成一个 Worker 需要Cloudflare API Token（账号级风险）；双 Worker + cron；令牌 7 天到期踩边界；硬编码 f005.backblazeb2.com 与图片后缀；match(...)[0] 可能为 null 直接 500

关键设计结论

  1. 砍掉第二个 Worker 与 cron：S3 SigV4 用永久密钥即时签名，天然替代「B2 令牌 7 天轮换」整套机制，同时消除 Cloudflare API Token 这个最大攻击面。
  2. 依赖归零：自实现 SigV4，并用 AWS 官方测试向量（20150830T123600Z）对拍验证；省掉 esbuild 打包、.html loader、TS 编译这些易碎环节，可直接粘贴到控制台部署。
  3. 只读 → 读写闭环：补上上传 / 删除 / 复制 / 重命名 / 建目录与可视化管理器，且不牺牲原有的 CDN 加速与零流量成本。
  4. 大文件不穿 Worker：预签名直传 + S3 分片上传，绕开 Workers 100MB 请求体上限；complete 阶段服务端自行 ListParts 取 ETag，规避跨域 ETag 暴露问题。
  5. 下载强制经 Worker：不签发任何 GET 预签名直链，?dl=1 由 Worker 下发附件头——端点、桶名、keyID 再也不会出现在下载链接里，同时让缓存 / 权限 / Range 策略统一生效。
  6. 默认安全：匿名只能读 /share/ 前缀；未配置凭据时写操作默认拒绝（fail-closed）；../ 归一化防穿越；匿名视图隐藏桶名与区域、剥离 x-bz-* 等内部响应头。

权限模型

Worker 侧完全无状态——没有 Cookie、没有 Session、没有 KV。每个请求独立判定一次 Authorization：Bearer（ADMIN_TOKEN）优先，其次 Basic（ADMIN_USER / ADMIN_PASS），比较全部走 SHA-256 + 逐位异或的恒定时间算法。所谓「保持登录」其实是浏览器按 origin + realm 缓存了 Basic 凭据，之后同源请求自动带上。

操作匿名 / 未登录管理员（Basic 或 Bearer）
读取 /share/**（PUBLIC_PREFIX 可配）✅✅
读取其它 key❌ 403✅
列举 /share/✅（PUBLIC_LIST=true）✅
列举其它目录❌ 403✅
访问根路径 /302 → /share/列出全桶
上传 / 删除 / 重命名 / API❌ 401✅

前缀是目录级匹配：share 与 share/a/b.jpg 命中，sharex.txt 不命中。把 PUBLIC_PREFIX 设为空字符串即可恢复「整桶匿名可读」。

上传流程

界面提供两种上传方式（下拉框切换，选择记在 localStorage），任一种超过阈值都会自动走 S3 分片上传，区别只是分片落在哪里：

路径数据路径需要桶 CORS单请求上限适用
① 直传 · 单文件浏览器 → 预签名 URL → B2是无≤ MULTIPART_THRESHOLD
② 直传 · 分片逐片取预签名 URL → B2是无>100MB，最快
③ Worker 代理 · 单文件浏览器 → Worker → B2否100MB没配 CORS 时
④ Worker 代理 · 分片逐片经 Worker 中继否单片 <100MB>100MB 兜底，较慢

分片时序：POST /__api/multipart/create 拿 uploadId → 逐片 GET /__api/multipart/part（直传）或 PUT（中继）→ POST /__api/multipart/complete（服务端 ListParts 取 ETag 后合并），失败可 /abort 清碎片。

>100MB 能否经 Worker 上传？能，但只能走「Worker 代理 + 分片」：每片 ≤ MULTIPART_PART_SIZE 且 <100MB，逐片转发，代价是两跳带宽、占 CPU/内存且更慢。想快就在 B2 桶配好 CORS 后用直传。

下载路径

GET /<key>             浏览器内联预览（图片 / 视频等，支持 Range 断点续传）
GET /<key>?dl=1        强制另存为（Worker 下发 Content-Disposition: attachment）
GET /<prefix>/         目录索引（HTML；?format=json 返回 JSON；?cursor= 翻页）

预签名 URL 现在只用于上传直传，type=get 会直接返回 403；原先的 ?redirect=1 302 直链跳转也已移除。这样做的收益：① 下载链接里不再出现 s3.<region>.backblazeb2.com、桶名与 keyID；② 权限、缓存、Range、防盗链策略全部在 Worker 一层统一生效。

CORS 配置

谁在限制？浏览器执行同源策略：页面在 https://你的域，却要 PUT 到 https://s3.<region>.backblazeb2.com，带自定义头就必须先过 OPTIONS 预检；而 B2 官方默认拒绝预检请求（“By default, the Backblaze B2 servers will deny preflight requests”）。所以：限制由浏览器执行，钥匙在 B2 桶上。非浏览器客户端（curl / rclone / aws-cli）完全不受影响。

为什么控制台里找不到？B2 网页控制台没有 CORS 设置界面，只能走 b2_update_bucket API、B2 CLI 或 S3 的 PutBucketCors。

b2 update-bucket \
  --corsRules '[
    {
      "corsRuleName": "allow-worker-b2-upload",
      "allowedOrigins": ["https://b2.edgeoneai.cc.cd"],
      "allowedOperations": ["s3_put", "s3_get", "s3_head"],
      "allowedHeaders": ["content-type", "x-amz-content-sha256"],
      "exposeHeaders": ["ETag"],
      "maxAgeSeconds": 3600
    }
  ]' axyz-bucket allPrivate

实测更正：官方文档把操作写成 S3 Put Object 这类带空格形式，但 API 实际返回 400 unknown allowedOperation value。真正可用的是小写下划线：s3_put / s3_get / s3_head / s3_delete（原生侧为 b2_upload_file / b2_upload_part / b2_download_file_by_name 等）。

另外，若桶上已有 Native 规则，S3 的 PutBucketCors 会被拒（The bucket contains B2 Native CORS rules），只能用 b2_update_bucket。

仓库里带了一个幂等脚本，支持多来源合并与逐来源预检自证：

B2_KEY_ID=xxx B2_APP_KEY=xxx \
B2_ORIGIN='https://a.example.com,https://b.example.com' \
node tools/setup-b2-cors.mjs

# [6] 模拟浏览器 OPTIONS 预检
#     ✅ https://b2.edgeoneai.cc.cd -> HTTP 200 | allow-methods: PUT

快速开始

1. 准备 B2 密钥

B2 控制台 → Account > Application Keys → Add a New Application Key，只给目标桶的最小权限：listBuckets（$path/$host 模式需要）、listFiles、readFiles、writeFiles、deleteFiles。同时记下桶的 Endpoint，形如 s3.us-west-001.backblazeb2.com。

2. 部署

git clone https://github.com/sdise/cf-b2.git && cd cf-b2
git checkout hy4-preview
npx wrangler login
npx wrangler secret put B2_KEY_ID
npx wrangler secret put B2_APPLICATION_KEY
npx wrangler secret put ADMIN_PASS
npx wrangler deploy

也可以不要本地环境：Workers 和 Pages → Create Worker → 粘贴 src/b2-worker.js 全文 → Deploy，然后在 Settings → Variables 里填明文变量与 Secrets。

3. 验证

# 健康检查（匿名只返回最小信息）
curl https://<你的域名>/__api/health

# 公开目录（匿名可读）
curl "https://<你的域名>/share/?format=json"

# 上传（Basic 鉴权，≤100MB 走 Worker 代理）
curl -u admin:你的密码 -X PUT --data-binary "@./test.txt" https://<你的域名>/test.txt

# 下载（经 Worker，强制另存为）
curl -OJ "https://<你的域名>/test.txt?dl=1"

# 网页管理器
浏览器打开 https://<你的域名>/__manage

直传须知：浏览器用预签名 URL 直传时，B2 桶必须配置 CORS（allowedOperations 用 s3_put），否则报 network error。不想配 CORS 就把上传方式切到「Worker 代理」。

成本：CF ↔ B2 同属带宽联盟，回源与出网免费，真正的成本只有 Workers 请求数与 B2 存储量。建议给 /share/* 加 Cache Rule + 对非公开路径加 WAF 速率限制。

安全：不要把 wrangler.toml / .dev.vars 提交到公开仓库，密钥一律走 wrangler secret put；未配置 ADMIN_* 时所有写 / 删操作默认拒绝；Basic 凭据的退出受浏览器缓存限制，需要即时失效请用 Bearer 令牌模式。

踩坑记录

  • ListObjectsV2 的 prefix 必须带尾斜杠：prefix=share 会让 share/ 下所有对象被折叠成一个 CommonPrefix，页面表现为「1 个目录 / 0 个文件」，文件全部消失。已改为目录前缀强制补 /。
  • CORS 操作名与文档不符：官方文档写 S3 Put Object，实测必须写 s3_put；桶上已有 Native 规则时 S3 的 PutBucketCors 不可用。
  • Cloudflare 会改写 HEAD 子请求为 GET导致签名失效，所以代理下载统一用 GET 发起、丢弃响应体。
  • Cloudflare 有时忽略 Range（响应缺少 content-range），需要带 AbortController 重试最多 3 次。
  • 不能把 accept-encoding / cf-* / x-forwarded-* 纳入签名：CF 会改写这些头，否则 SignatureDoesNotMatch。
