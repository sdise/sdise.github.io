测量原理与已知限制（建议先看一眼）
  • 浏览器 没有原始 socket，无法发送 ICMP / 裸 TCP 报文。这里用一次 HTTPS 请求的完整往返时间（含 DNS、TCP 握手、TLS 握手、首字节）作为延迟指标，多次取样取最小值最接近真实 RTT。
  • 只有当目标响应了 Timing-Allow-Origin 时，浏览器才会暴露 DNS / TCP / TLS / TTFB 分段耗时；否则只显示往返总耗时（表中记为「仅往返」）。
  • 本页通过 HTTPS 提供，浏览器会拦截 http:// 明文请求（混合内容），因此非 HTTPS 目标多半会失败——这是浏览器安全策略，不是工具故障。
  • HTTPS 目标需要有效证书。直接访问 IP（如 8.8.8.8）时若证书不匹配，会被判定为失败。
  • 请求使用 no-cors + HEAD 且不读取响应体，只建立连接、读取响应头，流量开销极小。

下载测速说明
  • 计时从第一个字节到达开始，把 DNS / TCP / TLS 握手排除在分母外，避免短文件测速被严重低估（旧版正是把连接建立时间算进了分母）。
  • 单条 TCP 连接受拥塞窗口与带宽时延积限制，往往跑不满带宽；并发 4~8 条更接近真实带宽。
  • 测速地址必须允许跨域（CORS）。speed.cloudflare.com 支持；自建源站请加上 Access-Control-Allow-Origin。
  • 下载的数据会被丢弃，不落盘、不缓存；流量消耗 = 并发数 × 每流大小（有上限保护）。

上传测速说明
  • 发送的是随机字节（不可压缩），多次 POST 直到到达时长上限；计时尚未扣除服务端处理与响应往返，结果略偏保守。
  • 目标端点需允许跨域 POST。speed.cloudflare.com/__up 支持。
  • 单次请求体越大越接近真实吞吐，但受浏览器内存与 Workers 请求体上限影响，建议 2~8 MB。
