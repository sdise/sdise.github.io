vpngate-test：把 VPNGate 节点检测与 VLESS 链接转换搬进浏览器

一句话概括：把以前要在本地跑 Python 脚本才能做的事 —— 验证 VPNGate 节点还活着吗 —— 做成一个单文件 Cloudflare Worker：粘贴节点（或整段 vpngate.csv），在 Cloudflare 边缘节点上直连目标做一次完整的 SSTP 握手，把还能用的挑出来，再一键转成可以直接导入 v2rayN / Shadowrocket 的 vless:// 链接。不装任何东西，浏览器打开即用。

在线预览 GitHub 仓库 部署文档

Cloudflare Workers SSTP / PPP VLESS / XHTTP SSE 流式结果 单文件零依赖 协议研究 · 学习性质

在线预览：https://vpngate-test.edgeoneai.cc.cd/（可直接拿去用；也能用一键部署按钮部署到自己的 Cloudflare 账号）

为什么做这个

我维护过一个 vpngate 项目：每小时抓 VPNGate 官方 API 入库，每天用 xray 内核逐条实测，只把有效的做成订阅。但那套流程是「GitHub Actions + xray 内核 + 十几分钟」，日常想临时看几个节点还活着没有，太重了。

于是先写了 scripts/sstp_check.py：纯标准库，直接对节点做 SSTP 握手，不需要 xray。它很好用，但仍然要求「有 Python 环境、会敲命令」。这次的 vpngate-test 就是把它搬到浏览器里：

sstp_check.pyvpngate-test
运行环境本地 Python 3（标准库）Cloudflare Worker（边缘节点）
要装什么需要 Python什么都不用，打开网页
交互命令行 --file / --csv / --linkWeb 界面 + HTTP API
检测内容SSTP 握手（+ 可选 TCP 出网）完全相同
输出stdout / --out 文件界面结果 + 复制 / 下载 + vless:// 链接

功能一览

功能说明
解析 / 提取从混乱输入里抠出「主机名/IP:端口」。支持单行、多行、多种格式混写，自动去重（按 host:port），# 开头的行视为注释
SSTP 实测直连每个节点，完整跑一遍 SSTP 建链 + PPP 协商，拿到虚拟 IP 才算有效；可选再经隧道做一次 TCP 三次握手，验证节点真能出网
实时输出SSE 流式推送，逐条刷出结果（成功 / 失败、耗时、分配到的 IP），带进度条与统计
转 vless 链接批量把 主机名/IP:端口 转成 vless://，UUID、入口、SNI、传输类型、global 全部可自定义
HTTP API/api/parse、/api/test（SSE）、/api/convert，可以 curl 或接到自己的流水线里
暖色 / 暗色右上角一键切换，选择记在 localStorage，默认暖色

支持的输入格式

单行、多行、混合都可以，空行与 # 注释行会跳过：

格式示例
主机名:端口vpn228702251.opengw.net:1587
IP:端口 / IPv6220.233.92.218:1587、[2001:db8::1]:443
只有主机名vpn228702251.opengw.net（用「缺省端口」，默认 443）
sstp 链接sstp://vpn:vpn@vpn228702251.opengw.net:1587
vless 链接自动从 path 里的 fdip=sstp://… 取出真实节点，#fragment 当备注
vpngate.csv含表头 Country,Hostname,IP,Speed_Mbps,TCP_Port，整段粘贴即可
VPNGate 官方 API CSV字段名自动识别（#HostName / IP / TCP_Port …）
空格分隔Japan vpn228702251.opengw.net 1587

CSV 会扫前 5 行找表头，按列名匹配：主机列取 Hostname/HostName/Host（取不到就退回 IP 列），端口列取 TCP_Port/Port/TCP，国家列取 Country/CountryLong/CountryShort/Region（用于生成备注），速度列取 Speed_Mbps/Speed。引号包裹的字段按标准 CSV 规则处理，所以 Croatia (LOCAL Name: Hrvatska) 这种带括号的国家名不会被逗号切坏。

检测原理

和 sstp_check.py、cf-vpngate 完全一致的四步：

1) TLS 连上节点
   connect({ hostname, port }, { secureTransport: 'on' })
   VPNGate 节点用自签证书，Cloudflare 出站 TLS 不阻断自签，能连上

2) 发一个「永不结束」的 HTTP 请求，把这条 TLS 流变成全双工 SSTP 隧道
   SSTP_DUPLEX_POST /sra_{BA195980-CD49-458b-9E23-C84EE0ADCD75}/ HTTP/1.1
   Host: <节点主机名>
   Content-Length: 18446744073709551615
   SSTPCORRELATIONID: {<uuid>}
   → 服务端回 200 即建链成功

3) 同一流里发 SSTP 控制报文 MSG_CALL_CONNECT_REQUEST（封装协议 = PPP）
   + SSTP 数据报文（载荷是 PPP 帧）

4) PPP 协商
   LCP   Configure-Request / Ack       → 链路参数协商（MRU 1500）
   PAP   Authenticate-Request          → 账号密码固定 vpn / vpn
   IPCP  Configure-Request / Nak / Ack → 服务端分配虚拟 IPv4
   → 拿到 IP 即判定该节点有效

勾选「额外验证出网」后，还会在 PPP 之上手工构造 IPv4 + TCP 报文（自己算首部与伪首部校验和），对目标完成 SYN → SYN+ACK → ACK，证明这个节点不只是握得上手，还能把流量真的送出去。

它验证的是「这个 VPNGate 节点本身还活着」，不是「入口 + 节点整条链路可用」。要测整条链路，得把生成的链接导入客户端实测，或用 vpngate 项目里的 xray 实测脚本。

链接转换：六个可自定义项

「转换为 vless 链接」按界面里的参数生成，生成结果与 vpngate 订阅里的链接同构：

vless://{UUID}@{ENTRY_HOST}:{ENTRY_PORT}
  ?encryption=none&security=tls
  &sni={SNI}&fp=chrome&type=ws
  &alpn=h3,h2&host={SNI}
  &path=/fdip=sstp://vpn:vpn@{节点}:{端口}?ed=2560[&global=1]
  #vpngate.me | {国家} | {短主机名}
参数默认说明
UUID495c7195-…必须与服务端一致，否则鉴权直接失败
ENTRY_HOSTsaas.sin.fan入口地址，域名或 IP 都行；必须是运行 cf-vpngate 类服务端的接入点
ENTRY_PORT443入口端口
Host / SNIsnip.edgeoneai.cc.cdTLS 的 SNI，同时作为 WS / XHTTP 请求的 Host
TYPEwsws 或 xhttp（xhttp 会自动补 mode=stream-one 与 alpn=h2）
GLOBAL不追加三态：不追加 / global=1（强制走 SSTP 落地）/ global=0（不强制，先直连）
ed2560Early Data 长度
备注模板vpngate.me | {country} | {name}可用 {country} {name} {host} {port}

「两段式」结构值得单独说明：入口固定（@ 后面是 VLESS + TLS + WS 接入点，SNI 与 Host 伪装成同一个域名），出口每条不同（path 里的 /fdip=sstp://vpn:vpn@节点:端口，入口收到连接后用 SSTP 拨号到对应节点，再把流量桥回去）。所以换节点只需要换 path，入口完全不用动。

转换范围有限，先看清楚：这里只生成 VLESS + WebSocket/XHTTP + TLS 这一种链接（security 恒为 tls、encryption 恒为 none），不支持 Reality / 非 TLS，也不做 trojan / vmess / ss 与 TCP / gRPC / HTTPUpgrade 的转换。

另外选了 xhttp 时要注意：客户端 xhttp 的 extra 必须与服务端一致，否则握手会失败或直接超时。界面里选 xhttp 会自动展开一份常用 extra 供照抄：

{
  "extra": {
    "noGRPCHeader": true,
    "headers": { "Content-Type": "application/octet-stream" },
    "xPaddingBytes": "100-1000",
    "xPaddingObfsMode": true,
    "xPaddingMethod": "tokenish",
    "xPaddingPlacement": "queryInHeader",
    "xPaddingHeader": "X-Cache",
    "xPaddingKey": "_dc"
  }
}

实现上的几个点

  • 单文件：整个项目就一个 worker.js（含内嵌前端页面），没有构建步骤、没有依赖，既能 wrangler deploy，也能整段粘贴到 Cloudflare 控制台；
  • SSE 流式：检测接口用 text/event-stream 逐条推 start / result / warn / done 事件，前端用 fetch + getReader() 手解析（EventSource 不支持 POST），100 个节点也能实时看到进度；
  • 并发池 + 截止时间：并发数、单节点超时、整轮最大时长都可调，到点停止剩余节点并推一条 warn；
  • BYOB 读 + 跨包拼接：SSTP 报文要按长度精确读，用 getReader({mode:'byob'}) + readAtLeast() 零拷贝拼接；
  • 配置三层合并：请求参数 > 环境变量 > 代码里的默认值，所以同一个部署既能改环境变量定默认，也能在界面上临时覆盖。

踩到的坑

现象原因与处理
Can't set compatibility date in the future: 2026-09-28（code 10021）构建发生在 UTC 2026-09-27 18:26，而我把 compatibility_date 按本地日期（UTC+8）写成了 9/28，对 Cloudflare 来说那天还没到。改成已过去的日期（现在固定 2026-09-25）即可。这个坑在「本地时区比 UTC 快」时必踩
一批节点全是 timeout先看端口：Cloudflare 的 connect() 会屏蔽一部分端口（常见如 22 / 23 / 25 / 110 / 143 / 465 / 587 / 993 / 995 / 6667…），VPNGate 有不少节点用 995，这类节点在 Worker 上会一律失败，不是节点挂了
并发开满后偶发中断检测主要是等网络 I/O（不计 CPU），但并发过高仍会撞 Worker 的 CPU 上限。免费计划建议并发 ≤10、单次 ≤50；整轮默认还有 240s 的时长上限
改了 [vars] 不生效环境变量改动必须重新部署一次（wrangler deploy 或让 Workers Builds 重新构建）

vpngate-test/
├── worker.js             # 全部逻辑：SSTP 探测 + 解析 + 转换 + Web 界面（单文件）
├── wrangler.toml         # name / main / compatibility_date / vars
├── package.json          # dev / deploy / tail / check
├── README.md             # 使用文档（输入格式、检测原理、API、FAQ）
├── DEPLOY.md             # 部署文档（一键按钮 / Workers Builds / 手动 / CLI）
├── scripts/              # 三个零依赖自检脚本
│   ├── check-ui.js       #   校验内嵌前端各 script 块语法
│   ├── check-parse.js    #   在 Node 里跑解析 / 转换逻辑
│   └── check-routes.js   #   冒烟测试 /、/api/parse、/api/convert、/healthz

三个自检脚本都是把 worker.js 里的 Cloudflare 专属 import/export 替换掉后塞进 Node 执行，所以不装 wrangler 也能跑，改完代码 npm run check 即可回归。

结语

这个项目本身不复杂，有意思的地方在于「把一套本地脚本的协议行为，原样搬到服务器端运行时」—— 报文格式、建链顺序、超时策略全都保持一致，于是本地 Python 版和 Worker 版可以互相印证：一边测出来有效、另一边无效，基本就能定位到是出口网络差异（端口屏蔽、节点对来源的限制）而不是代码问题。

配合已有的两个项目正好形成一条链：vpngate 负责批量采集与订阅，cf-vpngate 是服务端，vpngate-test 则是夹在中间的体检工具。

本工具只做公开数据的连通性检测与格式转换，不提供任何代理服务、不中转任何流量。VPNGate 节点由全球志愿者运行，流量经过第三方节点，请勿传输敏感信息；请遵守所在国家/地区的法律法规与 Cloudflare 服务条款。
